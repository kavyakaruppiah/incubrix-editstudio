# IncuBrix EditStudio Feature Status

Status reflects the implementation and tests inspected on 20 October 2026. “Implemented and tested” means there is direct automated-test evidence; it does not mean every configuration or media file has been verified.

## Implemented and tested

- Deterministic timeline edits, source-time mapping, anchored captions, undo/redo, and targeted restore. Unit, integration, and session coverage passes in the latest local full-suite run.
- Media intake and FFprobe inspection, transcript editing and export, background render/transcription jobs, and real FFmpeg rendering. Unit/integration coverage passes in the latest local full-suite run.
- Prompt parsing, clarification responses, project persistence, and a browser-based editing UI. Existing tests cover parser/API paths; the browser UI is served by FastAPI.
- The versioned `/api/v1` API and OpenAPI schema are present.
- Development server and Docker port publishing default to localhost; CORS is restricted to the local UI origins.
- Readiness/UI status distinguishes FFmpeg/storage readiness from whether the Faster-Whisper library is installed, instead of implying ASR is always operational.
- Projects can now be renamed, linked to uploaded media, reopened with their saved source video in the preview, duplicated, and deleted without deleting referenced media. API/stream regression coverage passes in the latest full-suite run.
- Empty projects now disable media-dependent actions until a source video is loaded.
- Export UI exposes validated H.264 quality, frame-rate, and encoding-speed settings; accepted options are recorded in the render manifest and covered by tests.
- Clip-to-clip crossfade and dissolve transitions overlap both video and audio, reduce output duration by the overlap, and update source-to-output caption/overlay timing. The single-clip filter-label regression is covered by real FFmpeg tests.
- Time-range tool schemas accept the parser's normalized `start_time`/`end_time` fields consistently for cut, keep, speed, mute, and bleep operations. Regression coverage includes the Thanglish “mudhal 10 seconds cut pannu” prompt and apply path.
- “Remove the part about pricing” now searches a small, explicit financial-term synonym set (including `pricing`/`cost`); multiple transcript matches ask which occurrence before changing the timeline. The chosen word IDs stay visible in the proposed operation.
- Bleeping a transcript word with confidence below 0.5 or a transcript warning is rejected with a word-specific explanation; time-range bleep remains available when the user supplies exact timestamps.
- API write requests now require `Idempotency-Key`; the browser creates keys automatically, remaining JSON write routes share a retry cache, and the OpenAPI document marks the header required. Transcript uploads hash both content and media identity so retries do not reapply changes.
- An OpenTimelineIO JSON export endpoint and UI download button now export source-linked video/audio clips, source ranges, speed effects, timeline identity, captions, overlays, and IncuBrix effect metadata. API structure and download headers are covered by an integration test. Transition objects and native translation of global effects are not emitted, and the official OTIO library round-trip could not be run in this restricted environment; this is an initial interchange export, not yet full-fidelity OTIO conformance.
- Audio-aware cut snapping now receives transcript word timings: a boundary inside a word expands to that word's start/end according to cut role, and candidate low-energy frames inside protected words are excluded. The applied operation reports snapping metadata. Word-edge fallback behavior has focused tests, and the rendered session's expected duration reflects the actual snapped source interval.
- Sentence and speaker-labelled captions shorter than 0.7 seconds are extended to a readable minimum where timeline duration permits; captions never extend beyond the output. A sped-up-caption timing regression test covers the behavior. Word-by-word and karaoke timing retain their per-word timing to avoid creating overlapping display events.
- CI now includes 40 full YAML session scripts plus a 50-case offline prompt scenario matrix. Every session runs three times in CI and checks identical final timeline hash and duration; every step's output is checked for a valid three-way status, timeline hash, and duration. The session pack has expected last statuses, but only selected scenarios assert detailed expected timelines or rendered output; this does not prove every edit combination frame-accurate.
- Local-model planner payloads now omit transcript words for edits that do not depend on speech; content-driven prompts receive bounded lexical match windows across the full transcript or distributed excerpts, with speaker/confidence metadata. The Ollama JSON schema is narrowed to likely tools when the prompt has clear operation cues and falls back to the complete registry for unknown wording. Regression tests cover late-transcript retrieval and safe broad fallback.

## Implemented but not fully verified

- `create_reel` prompt execution is dispatched to `TimelineEngine.apply_create_reel`. A regression test covers applying a 30-second vertical reel; it passes in the latest suite.
- Multi-operation plan approval skips unsupported/unclear parts, applies independent validated operations, and returns `partial` with reasons. If an actual supported operation fails during execution, the entire plan still rolls back. The frontend displays partial success and skipped work distinctly.
- The complete storyboard flow, including reel creation, captions, title overlays, and final render. The latest full suite verifies this end-to-end flow successfully.
- Tamil/mixed-language captions, optional Faster-Whisper transcription, background music, and render verification. Their availability depends on installed models, fonts, and FFmpeg build features.
- Optional Google speech fallback is disabled by default and requires explicit `GOOGLE_SPEECH_FALLBACK_ENABLED=true`; the no-network-by-default behavior has a passing regression test.
- Local Ollama prompt planning now uses typed JSON tool actions with per-operation parameter schemas, media metadata, and transcript context. Actions are validated and passed directly to the deterministic timeline engine rather than reparsed as text. `INSTRUCTION_PROVIDER=auto` prefers local Ollama and visibly falls back to offline rules when the model is unavailable. Local models installed: Qwen2.5 1.5B primary, Qwen2.5-Coder 1.5B fallback, and DeepSeek-Coder 1.3B available for opt-in evaluation. The coder fallback is used only when the primary plan is incomplete or invalid; common unrelated actions are filtered before review. Readiness reports the primary model available. A live plan-and-apply check succeeded. These models have not been fine-tuned; model-weight training requires a separately provisioned, licensed dataset and training workflow. DeepSeek-Coder is not enabled by default because its live video-edit plan was slow and unreliable.
- Gemini remains an optional cloud planner. In `auto`, it is tried only when local Ollama is unavailable and `GEMINI_API_KEY` is configured; otherwise the app uses its visible offline rules fallback. Provider response parsing is mock-tested, but live Gemini behavior, quota, and billing have not been verified. Ollama plan/apply quality likewise depends on the installed model and hardware.
- The direct `/api/v1/instruction/{media_id}` endpoint now uses the same structured local-AI planning and tool execution path as plan preview when provider mode is `auto` or `ollama`, preventing the UI/API entry point from silently routing novel prompts through the old keyword parser. In `auto`, Ollama outages still use the explicitly marked rules fallback; `ollama` mode returns an actionable failure.
- The registry validates parameter types, finite values, time-range ordering, and playback-speed bounds both when a structured plan is reviewed and when it is applied. Invalid structured actions fail the plan atomically instead of being silently skipped. `reorder_sections` is included in the discoverable tool registry. Normalized time aliases are accepted by all time-range tools; cinematic preset plans can include a descriptive `target: video` field without failing schema validation.
- In offline `auto` fallback, the synonymous phrase “remove silence and long pauses” is normalized to the supported silence-removal action instead of being falsely classified as an unparseable compound command.
- Optional ElevenLabs Scribe speech-to-text is wired as a transcription backend with word timestamps and speaker IDs. Its response mapping is mock-tested; a live transcription is unverified until the user configures an ElevenLabs key. Configuring it sends uploaded media to ElevenLabs and may incur usage charges.
- Background music ducking now uses FFmpeg `sidechaincompress` keyed from the source audio, then mixes the ducked bed under the original dialogue. A real FFmpeg render verifies that the filter graph executes and preserves an audio stream.
- Render jobs can now be canceled from the progress dialog. Queued jobs are removed before execution; active FFmpeg processes are terminated, partial output is removed, and job status remains `cancelled`. Focused job-manager tests and the existing real-render suite pass. Cancellation during slow output verification is reported as canceled and the generated file is deleted after verification returns.
- Prompt-driven audio noise reduction is now represented in timeline state and rendered with FFmpeg `afftdn`. Natural-language aliases validate in plans, plan approval updates the timeline, a source without audio is blocked clearly, and a real FFmpeg render test passes. This is spectral noise reduction, not AI vocal isolation.
- Prompt-driven quarter-turn rotation and horizontal/vertical mirroring are stored in video effect state and rendered through FFmpeg transforms before canvas fitting. Prompt parsing, plan approval, and real rotation/mirror renders have regression coverage.
- The canvas panel exposes 16:9, 9:16, 1:1, and 4:5 presets. Selecting a preset uses the existing reversible aspect-ratio operation, updates the selected button from persisted timeline state, and renders without stretching source footage. The 4:5 path is verified with a real 1080×1350 FFmpeg output and preserved audio.
- Ending-speed wording (for example, “Change the speed of the ending to 1.5x”) now maps to a calculated ending range and applies through the timeline speed operation. Parser aliases, plan approval, and real FFmpeg segment-speed rendering are covered.
- FFmpeg/FFprobe configured paths that cannot be inspected due to an OS permission error now fall through to PATH/package discovery instead of crashing health/readiness or media intake during path resolution.
- Caption plans now auto-start the configured transcription job when there is no transcript, then apply word-anchored captions. Empty transcripts no longer create fake clip-label overlays. A real FFmpeg render regression verifies the generated ASS subtitle file and burn-in filter execute successfully.

## Partially implemented

- Local model reviewed plans use dynamic language understanding, but execution is limited to the editing capabilities registered and implemented by the timeline/FFmpeg engine. Unsupported requests are reported rather than silently applied. Without Ollama installed and running, the offline fallback uses the deterministic parser; no system can fulfill effects that the renderer does not implement.
- The frontend is a static HTML/CSS/JavaScript application. It has a video preview, transcript tools, prompt input, multitrack timeline visualization, drag-and-drop video clip reordering, export flow, and 16:9/9:16/1:1/4:5 canvas presets, but not all detailed object/property controls in the specification.
- Timeline history supports undo/redo and revision/operation restore. Whole-plan rollback is implemented and covered by regression tests.
- Export supports user-selectable H.264 quality, encoder speed, and frame rate, alongside existing aspect-ratio choices; codec and destination selection are not present.
- Background jobs expose status and render cancellation; reliable ETA and crash recovery are not implemented as complete workflows. Transcription-job cancellation is still unavailable.
- Local storage is implemented. S3 adapter code exists, but deployment and integration coverage are limited.

## Not implemented

- Audio waveform display, keyframe animations, layer ordering, and reusable saved design presets. Video clip drag/reorder is implemented and verified through the API; the remaining visual editing controls are still missing.
- A complete security and resource-control policy covering upload duration/disk limits and authentication for intentionally network-exposed deployments.
- Verified package/model/font licence inventory and FFmpeg build obligations for commercial distribution. `SOURCES.md` and `AI_USE.md` exist, but legal suitability still needs a human review.

## Assessment 2 readiness

The attached brief defines a scoped prompt-driven editing engine, not Adobe Premiere feature parity. It requires a fixed set of deterministic operations, content-anchored edits, reversible history, correct rendering, three-way responses, a session runner, and a working review deployment. Natural-language understanding can choose among implemented tools; it cannot safely create an effect the timeline and renderer do not implement.

- **Must-haves:** source preservation, deterministic history, core edit operations, API, and session-runner coverage exist. The cut/mute/bleep/speed parameter mismatch found during prompt review is fixed and regression-tested. Render timing is exercised by real FFmpeg tests, but broad frame-accurate A/V verification across all edit combinations still needs expansion.
- **Core level:** substantially implemented, but the exact eight-step worked example and all required single/multi-speaker cases need to be run and retained as submission evidence on owned test media.
- **Advanced level:** partial. Transcript ambiguity and anchoring exist, with a tested pricing-to-cost semantic search case; sentence-caption minimum display timing is implemented, but word-by-word/karaoke minimum timing, advanced caption-edit rules, broad meaning-based search, precise multi-speaker lead-in handling, and remaining conflict cases need more coverage.
- **Outstanding level:** incomplete. A source-linked OTIO JSON export is implemented with structural API coverage, but transition/native effect fidelity and library round-trip validation remain. Word-aware cut snapping is implemented with focused tests. A reproducible local-model latency benchmark exists; an actual one-run synthetic transcript measurement on this host returned 32.69s for 5 minutes and 34.73s for 60 minutes (Qwen2.5 1.5B), which fails the <3s target. This is preliminary single-sample evidence and requires the documented multi-run benchmark on target hardware. Comprehensive low-confidence/overlap/VFR evidence also remains. CI now executes 40 full session scripts three times and compares hashes/durations, alongside the 50-case prompt matrix; detailed render expectations and frame accuracy still need broader assertions.
- **Integration:** versioned API, OpenAPI, Docker, required write idempotency, JSON errors, health checks, manifest, and batch/session runner are present. A GitHub Actions workflow now runs the full test suite; its first hosted run is not yet verified. A reviewer live demo, callback signing, robust job recovery/cancellation, verified S3 deployment, and external-deployment authentication remain incomplete or unverified.
- **Model training:** local Qwen and DeepSeek models are not fine-tuned. The design constrains models to typed edit proposals and keeps timeline mutation deterministic; training would require a licensed prompt-to-operation dataset and suitable compute, and would not add renderer capabilities by itself.

This is not yet an Adobe Premiere replacement or a verified claim that every assessment must-have passes. It is a substantial engine prototype with a passing automated suite and identified remaining evidence and feature gaps.
